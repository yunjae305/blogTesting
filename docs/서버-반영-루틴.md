# 서버 반영 루틴 — 로컬 수정을 서버 PC에 올릴 때

작성 2026-08-18. 처음 설치하는 절차가 아니다 — 그건
[서버-설치-절차.md](서버-설치-절차.md)를 본다. 이 문서는 **이미 돌고 있는 서버에
로컬 수정본을 반영할 때** 서버 쪽에서 무엇을 해야 하는지만 적는다.

## 요약

**대부분의 배포는 "복사 + 재시작"이 전부다.** 아래 조건부 표에 해당할 때만 한 가지씩
더 한다. 어떤 배포에 조건부 작업이 필요한지는 그날의 `변경내역/` 문서에 적혀 있다 —
배포 전에 그것부터 훑는다.

## 1. 매번 하는 것

### 로컬에서 (복사 전)

```powershell
cd apps/web ; npm run build      # 프런트를 건드렸으면. dist가 함께 복사된다
```

### 복사

**서버 PC에서** (RDP 드라이브 공유가 켜져 있으면 로컬 C:가 `\\tsclient\C`로 보인다):

```powershell
robocopy \\tsclient\C\Blog-it\apps C:\blog-it\apps /MIR /XD node_modules __pycache__ /XF *.pyc /R:2 /W:2 /NFL /NDL
```

robocopy 증분 복사라 바뀐 파일만 옮긴다 — 첫 복사 9MB 미만, 두 번째부터는 몇 초다.
`__pycache__`·`node_modules`는 제외된다(서버가 스스로 다시 만든다). 수동으로 한다면
`apps/` 폴더를 서버(`C:\blog-it`)에 덮어쓴다. 필요하면 `docs/`·`변경내역/`도.

**절대 덮어쓰면 안 되는 것:**

| 항목 | 이유 |
| --- | --- |
| **`.env`** | 서버 전용 값이다 — Mongo가 localhost+인증 계정이고, 로컬은 Atlas다. 덮어쓰면 서버가 엉뚱한 DB로 붙는다 (2026-08-18에 실제로 일어났다) |
| `.naver-profile-users`, `.threads-profile-users` | 로그인 세션·암호화 계정정보. 암호화가 PC의 Windows 계정에 묶여 있어 옮겨도 못 풀고, 덮어쓰면 서버 사용자들의 세션만 날아간다 |
| `.auth-secret` | 토큰 서명 키. 서버 `.env`에 `AUTH_TOKEN_SECRET`이 있으므로 어차피 무시되지만, 원칙상 로컬 상태 파일은 옮기지 않는다 |
| `node_modules`, 각종 캐시(`.pytest_cache` 등) | 런타임에 불필요 |

### 서버에서

```powershell
cd C:\blog-it
.venv\Scripts\python.exe apps/api/scripts/serve.py
```

파이썬 코드는 **재시작해야 반영된다.** 작업 스케줄러로 상시 구동 중이면 그 작업을
끝냈다가 다시 시작한다. 이전 백엔드가 열어 뒀던 크롬 창이 남아 있어도 신경 쓸 것
없다 — 다음 발행이 자동으로 정리한다(browser_reaper·고아 크롬 복구).

### 접속하는 브라우저에서

Ctrl+F5 (강력 새로고침). 옛 번들이 탭에 남아 있으면 새 화면이 안 보인다.

## 2. 바뀌었을 때만 하는 것

| 이럴 때 | 서버에서 |
| --- | --- |
| `apps/api/requirements.txt`가 바뀜 | `.venv\Scripts\python.exe -m pip install -r apps/api/requirements.txt` |
| `scripts/init_mongo.py`의 검증기·컬렉션이 바뀜 — 특히 저장 모델에서 **필드를 지웠을 때** (CLAUDE.md의 Mongo 검증기 함정) | `.venv\Scripts\python.exe apps/api/scripts/init_mongo.py` |
| `.env`에 새 **필수** 변수가 생김 | 서버 `.env`에 그 줄만 추가. 기본값이 있는 변수는 안 넣어도 된다 |
| nginx 설정이 필요한 기능 (예: 라이브 뷰 프레임이 뭉쳐서 올 때 `/live/` 블록) | `C:\nginx\conf\nginx.conf` 수정 → `nginx -t` → `nginx -s reload` |

## 3. 안 해도 되는 것

- venv 재생성 — 한 번 만든 것을 계속 쓴다 (패키지 추가는 위의 pip install로)
- Mongo 계정·URI 변경 — 서버 `.env`에 있는 그대로
- 서버에서 `npm ci`/`npm run build` — 로컬 빌드(dist)를 복사하는 방식이다

## 4. 배포 후 확인 (30초)

```powershell
Invoke-RestMethod http://localhost:3000/health
```

- `storageStatus`가 `mongodb:blog_it`인가 — 인메모리면 `.env`가 잘못됐다
- 외부 PC에서 `http://<고정IP>:8888` 접속 → 로그인 → 화면 한 번

## 5. 서버 기본 정보 (2026-08-18 기준)

| 항목 | 값 |
| --- | --- |
| 저장소 경로 | `C:\blog-it` |
| 백엔드 실행 | `.venv\Scripts\python.exe apps/api/scripts/serve.py` |
| 백엔드 포트 | `.env`의 `PORT` = 3000 (`serve.py`가 이 한 곳만 읽는다) |
| 외부 노출 | nginx 8888 → 127.0.0.1:3000 |
| Mongo | localhost:27017, DB `blog_it`, **인증 켜짐** — 계정은 서버 `.env`의 `MONGODB_URI`에 (`blogit_app`, authSource=blog_it) |
| 상시 구동 | 작업 스케줄러 · 인수 `apps\api\scripts\serve.py` · "사용자가 로그온한 경우에만 실행" |
| 주의 | 발행 크롬 창을 **최소화하지 말 것**(라이브 뷰가 멈춘다). 다른 창으로 덮는 것은 무방 |

## 6. 기록 규칙

수정 작업이 서버 반영을 요구하면(패키지 추가·검증기 변경·필수 env 변수·nginx),
그날 `변경내역/` 문서에 **"서버에서 할 일"** 로 명시한다. 배포하는 사람은 마지막
배포 이후의 변경내역만 훑으면 조건부 작업을 놓치지 않는다.
